# v2.2.2 发布说明 — 选择题定期提醒

> 小功能版本（patch，用户明确指定递增至 2.2.2）。本轮新增「选择题定期提醒」机制：在微信端与 DSH 端都没有操作的情况下，每隔一段时间在微信再次推送一条带选项与回填码的提醒，避免选择题迟迟未操作却只等来超时提示。插件仍不接管会话生命周期。完整架构背景见 [v2.2.0 发布说明](RELEASE_NOTES_v2.2.0.md)。

## 一句话

选择题发起后若两端都无人操作，每 60 秒在微信补推一条「仍待选择」提醒（含问题、编号选项与回填码），最多 3 次；任一端作答或到达 5 分钟硬超时即停。

## 新增功能

### 选择题定期提醒（m02017）

- **背景**：用户反馈「选项卡没推送到微信，只等来超时提示」。此前选择题只有 5 分钟硬超时、无任何提醒，用户容易误以为回填失效。
- **复用现成轮子**：审批（ApprovalRegistry）已有提醒机制（`remindIntervalMs` 默认 60s、`maxReminders` 默认 3、`onRemind` 回调）。选择题原先没有，本轮对齐该范式。
- **新增配置**：
  - `questionRemindIntervalMs`：提醒间隔，默认 60s，回落 `remindIntervalMs`。
  - `questionMaxReminders`：最多提醒次数，默认 3，回落 `maxReminders`。
- **行为**：
  - 每到期推一条 `[提醒] 选择题仍待选择` 文本，含问题、编号选项（`A. 甲` / `B. 乙`）与回填码（单题 `前缀 1A`、多题 `前缀 1A 2B`）。
  - 到顶（3 次）只停提醒、不自动跳过；5 分钟硬超时才关闭回填。
  - 任一端作答（微信回填 / DSH 手选）立即停：`finish` / 超时 / UI 胜出 / dispose 四处均调 `clearQuestionReminder` 清理定时器，杜绝泄漏。

## 已知边界

- 提醒只补推文本提醒，不重复创建原生选项卡；用户仍可用提醒里的回填码直接作答。
- 到顶停止提醒不等于跳过题目；只有 5 分钟硬超时才关闭回填通道。
- 版本号由用户拍板升至 2.2.2；本发布说明随版本包发布，实际 npm/GitHub/Gitee 发布动作需用户另行确认。
